## INTERACTION PHILOSOPHY

### Core Beliefs

**1. Touch Targets are Sacred**
- 44x44px minimum (Apple HIG)
- 48x48px preferred (Fee standard)
- 8px minimum spacing between targets
- If users have to aim, we failed

**2. Feedback is Immediate**
- Tap: 150ms response
- Button press: Visual feedback (scale, color)
- Action complete: Toast notification
- Error: Clear message + solution

**3. Gestures are Optional**
- Tap is primary interaction
- Swipe is secondary (pull-to-refresh, dismiss)
- Pinch/zoom is rare (not needed)
- Long-press is rare (context menus only)

**4. Navigation is Obvious**
- Bottom navigation (3 tabs max)
- Back button always visible
- No hidden gestures
- No circular navigation
- No dead ends

**5. Loading is Transparent**
- Show loading state immediately
- Show progress when possible
- Show skeleton screens
- Never show blank screens
- Never make users guess

**6. Errors are Helpful**
- Explain what happened
- Explain why it happened
- Explain how to fix it
- Provide next steps
- Never show error codes

### Interaction Principles

**1. Responsive**
- < 100ms response to tap
- < 200ms response to action
- < 500ms animation duration
- < 2s load time

**2. Predictable**
- Same behavior across all screens
- Same behavior across all platforms
- No surprises
- No hidden behavior

**3. Forgiving**
- Undo actions (where possible)
- Confirm destructive actions
- Provide escape routes
- Don't punish mistakes

**4. Accessible**
- Keyboard navigation
- Screen reader support
- High contrast
- Large touch targets
- Reduced motion support

## MOTION PHILOSOPHY

### Core Beliefs

**1. Motion is Functional**
- Motion guides attention
- Motion shows relationships
- Motion provides feedback
- Motion is not decoration

**2. Motion is Subtle**
- 150ms: Micro-interactions (button press, toggle)
- 200ms: Small transitions (tab switch, modal)
- 300ms: Medium transitions (page navigation, expand/collapse)
- 500ms: Large transitions (screen changes, complex animations)
- Never exceed 500ms

**3. Motion is Purposeful**
- Every animation has a purpose
- No animation for animation's sake
- No decorative animations
- No attention-seeking animations

**4. Motion is Performant**
- 60fps minimum
- GPU-accelerated (transform, opacity)
- No layout thrashing
- No jank
- Respects reduced motion

### Motion Principles

**1. Easing**
- Ease-out: Entering screen (fast start, slow end)
- Ease-in: Exiting screen (slow start, fast end)
- Ease-in-out: State changes (smooth transition)
- Never linear (feels robotic)

**2. Choreography**
- Stagger animations (sequential, not simultaneous)
- Orchestrate complex animations
- Guide user attention
- Create visual hierarchy

**3. Feedback**
- Button press: Scale down (0.95) + color change
- Success: Checkmark scale in (1.0 → 1.2 → 1.0)
- Error: Shake (subtle, 200ms)
- Loading: Spinner (continuous, infinite)

**4. Transitions**
- Page navigation: Slide left (forward), slide right (back)
- Modal: Fade in + scale up (0.95 → 1.0)
- Toast: Slide up + fade in
- Bottom sheet: Slide up

**5. Reduced Motion**
- Respect `prefers-reduced-motion`
- Disable non-essential animations
- Keep functional animations (feedback, transitions)
- Provide alternative (instant transitions)

**1. Accessibility is a Right**

- Accessibility is a requirement

**2. Accessibility is Quality**
- Accessible design is better design

- Accessibility is not a burden

**3. Accessibility is Comprehensive**
- Visual (contrast, color, typography)
- Motor (touch targets, gestures)

- Keyboard (navigation, focus)

### Accessibility Principles

**1. Visual**
- WCAG AA minimum (4.5:1 contrast)
- WCAG AAA preferred (7:1 contrast)
- Color is not the only indicator
- Text is resizable (up to 200%)
- No information conveyed by color alone

**2. Motor**
- 44x44px minimum touch targets (Apple HIG)
- 48x48px preferred (Fee standard)
- 8px minimum spacing between targets
- No precise gestures required
- No time-limited interactions

**3. Cognitive**
- Simple language (8th grade reading level)
- Clear labels (no jargon)
- Consistent patterns
- No time pressure
- No memory required

**4. Screen Reader**
- Semantic HTML (headings, landmarks)
- ARIA labels (icons, buttons, inputs)
- Live regions (dynamic content)
- Descriptive text (context, purpose)
- Logical tab order

**5. Keyboard**
- All interactive elements accessible
- Logical tab order
- Visible focus indicators
- Keyboard shortcuts (where appropriate)
- No keyboard traps

## WHAT FEE SHOULD NEVER BECOME

### Never Become a Game

**❌ No Gamification**
- No fake urgency ("Limited time!")
- No fake scarcity ("Only 3 left!")
- No fake progress bars
- No fake achievements
- No fake rewards
- No fake levels (subtle progression is OK)
- No fake streaks (real streaks are OK)
- No fake bonuses

**Why**: Users trust us with their time and attention. Fake gamification breaks that trust.

**✅ What We Do Instead**:
- Real progression (levels based on actual FC earned)
- Real streaks (based on actual daily activity)
- Real achievements (based on actual milestones)
- Real rewards (FC that can be withdrawn)

---

### Never Become a Casino

**❌ No Gambling Mechanics**
- No loot boxes
- No random rewards
- No "spin to win"
- No "scratch to earn"
- No chance-based rewards
- No "jackpot" mechanics
- No "risk it all" mechanics

**Why**: Users trust us to pay them for their time. Gambling mechanics break that trust.

**✅ What We Do Instead**:
- Fixed rewards (users know exactly what they'll earn)
- Guaranteed earnings (complete task, get FC)
- Transparent odds (no hidden probabilities)
- No risk (users can't lose FC)

---

### Never Become a Mining App

**❌ No Mining Mechanics**
- No "tap to mine"
- No "hold to earn"
- No passive income claims
- No "energy" systems
- No "hash rate" mechanics
- No "mining pool" mechanics

**Why**: Users trust us to pay them for real work. Mining mechanics are fake and break trust.

**✅ What We Do Instead**:
- Real tasks (surveys, ads, app installs)
- Real work (users complete tasks, earn FC)
- Real value exchange (advertisers pay, users earn)
- Real settlement (FC converted to USD)
